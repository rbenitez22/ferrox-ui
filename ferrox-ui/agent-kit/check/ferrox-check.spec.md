# ferrox-check: the specification

`ferrox-check.sh` (bash) and `ferrox-check.ps1` (PowerShell 7) implement
this exactly; a test runs both against the same fixtures and requires the
same output. To use the check from another language, give this file and
`rules.tsv` to your agent and ask for the same program in that language;
the fixtures in `tests/` say whether it's right.

## What it does

Lists every place an app drifts from ferrox-ui (a hand-made control, an
inline style, a colour or size written out in CSS, a missing setup step),
each with the fix, and says whether there was any.

## Invocation

```
ferrox-check [folder]
```

- `folder`: the folder to check (an app's root, or any folder inside it).
  Default: the current folder.
- More than one argument, or a folder that doesn't exist: print
  `usage: ferrox-check.<ext> [folder]` to standard error, exit 2.

## The files checked

Every file under `folder` whose name ends in `.rs`, `.css` or `.html`,
except inside folders named `target`, `dist` or `node_modules`, folders
whose name starts with `.`, and any folder at a path ending in
`style/ferrox` (generated by the build). Each file is named by its path
relative to `folder`, with `/` between parts. Files are taken in bytewise
(ordinal) order of that path.

## The rules (`rules.tsv`)

UTF-8 text, one rule per line. Lines that are empty or start with `#` are
skipped. A rule's line has exactly seven fields separated by tab
characters; a field may be empty (two tabs in a row), and empty fields must
be kept (don't collapse runs of tabs):

| # | Field | Meaning |
|---|---|---|
| 1 | `id` | the rule's name: `raw-button` |
| 2 | `kind` | `forbid` or `require` |
| 3 | `files` | which files: `*.rs`, `*.css` or `*.html` (the file name ends with the part after `*`) |
| 4 | `pattern` | a regular expression |
| 5 | `except` | a regular expression, or empty |
| 6 | `rule` | the problem, in words |
| 7 | `fix` | what to do instead |

Rules are numbered 1, 2, 3… in file order (skipped lines don't count).

Patterns use only the subset of regular expressions that POSIX extended
(`grep -E`) and .NET agree on: literal characters, `.`, `[…]` and `[^…]`,
`*`, `+`, `?`, `{n,m}`, `|`, `(…)`, `^`, `$`, and `\` before a special
character to mean it literally. No `\b`, `\d`, `\s`, `[[:class:]]` or
lookarounds. A pattern matches a line if it matches anywhere in it
(unanchored, case-sensitive). Lines are read without their line ending.

## Checking

**`forbid` rules.** For each file the rule applies to, in file order, for
each line (numbered from 1) that the `pattern` matches: skip it if the
`except` pattern is non-empty and matches the same line; skip it if the
line, or the line just before it, contains the text
`ferrox-check: allow <id>` (a deliberate exception, written as a comment).
Otherwise it is a **finding**: file, line number, rule number.

**`require` rules** apply only when `folder` contains a file named
`Cargo.toml` (it's an app's root). If at least one checked file matches the
rule's `files`, and no line of any such file matches the `pattern`, the
rule is **missing**. If no checked file matches `files`, the rule is
skipped.

## Output

To standard output, one line each, in this order:

1. Every finding, sorted by file (in file order), then line number, then
   rule number:
   `<file>:<line>: <id>: <rule> (fix: <fix>)`
2. Every missing rule, in rule order:
   `<files>: <id>: <rule> (fix: <fix>)`
3. The summary: `ferrox-check: no drift` when there were none; otherwise
   `ferrox-check: <n> problem(s)`, where `<n>` counts findings plus
   missing rules.

Lines end with the platform's line ending. Nothing else is printed.

## Exit status

`0`: no drift. `1`: drift found. `2`: usage error.
